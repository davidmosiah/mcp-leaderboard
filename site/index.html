Method / fairness

Booted,
not guessed.

The scoring engine observes what an agent can actually discover and safely understand. The pipeline fails closed: incomplete runs never publish.

  1. 01
    Build the corpus

    Pull the official MCP registry, keep npm-installable active versions and deduplicate package identities.

  2. 02
    Run in isolation

    Boot each package over stdio in a clean process with hard timeouts and no production credentials.

  3. 03
    Score visible evidence

    Grade schemas, naming, descriptions, safety annotations, mutation gates, privacy, resources, discovery and smoke tests.

  4. 04
    Publish or stop

    Verify complete coverage, deterministic output and methodology compatibility before committing the static dataset.

Evidence boundary

A score is a map,
not a certificate.

The index measures agent-readiness shape and metadata. It does not certify correctness, security, uptime or business quality.

  • A score can be reproduced from the open-source engine.
  • Unreachable is a separate state, never a disguised zero.
  • Rank cannot be bought; the editorial surface contains no commercial placement.

For agents / researchers

Every surface has a machine-readable twin.

Use the exhaustive JSON dataset for analysis, llms.txt for a compact orientation, or the weekly feed for changes. The human pages and machine surfaces are generated from one committed source.

Run the instrumentShell
npx -y mcp-scorecard \
  <package-or-repository> \
  --json

Returns the 0–100 score, all ten checks and actionable gaps. It never invents a score when the package cannot be graded.

Questions / answersBefore you trust the index

Read the caveats first.

01How often does the index refresh?

A weekly Grok Cloud routine runs the complete corpus in a fresh ephemeral VM. It publishes only after coverage, metadata, weekly-edition and SEO gates pass. This Mac is not part of the scheduled pipeline.

02Why are some packages unreachable?

Auth gates, startup errors or timeouts can prevent fair inspection. Those packages remain visible in the dataset with an unreachable status rather than receiving a misleading low score.

03Can a maintainer influence the ranking?

Only by changing the public package and improving reproducible evidence. There is no manual score override, paid placement or private credential path.
